# Active implementation handoff: independent cabin lighting fixtures

**Status:** In progress; planning and asset audit only. No implementation for this expanded request has been committed yet.

**Branch:** `codex/independent-cabin-fixtures`

## User's requested outcome

Build on the existing 2D/3D cabin simulator so individual lighting sources can be selected on the aircraft mockup and controlled independently. The user specifically wants:

- Separate left and right sidewall light sources, with the count and placement appropriate to the selected aircraft and its cabin layout.
- Independent ceiling and recessed-ceiling sources.
- Window daylight sources.
- Individual passenger reading lights above the seats, near passenger service/call-button panels.
- RGBW color, brightness/intensity, lighting effects and scene fades for each source without changing other sources.
- The available source/zone inventory to follow the selected cabin and its rows/layout.
- Clickable sources in the existing 3D canvas, with their properties shown in the existing Zone Inspector.

The Studio interface is locked. Keep the current viewport-constrained layout, sidebar, panel positions, inspector, and choreography/scene panels unchanged. Add the controls within existing panels and canvas interactions. Do not add navigation items, resize/reorder panels, or change the approved interface. Keep all work in simulation; physical outputs stay disabled.

## GLB audit evidence (29 bundled models)

Files are catalogued by `assets/aircraft-data/catalog.json` and `assets/aircraft-data/airline-mesh-catalog.json`; inventory is generated by `assets/aircraft-data/generate_zone_availability.py`.

- Every one of the 29 bundled GLBs has two named `Ceiling cove` mesh components. These are existing independent geometry candidates and should not remain coupled to one color track if independently addressable controls are added.
- Every one has one actual named sidewall light-strip mesh on each side.
- Every one has eight named sidewall locator nodes per side (`left_sidewall fixture N` / `right_sidewall fixture N`). These nodes carry transforms but no mesh. They are authored locator positions, not visible lamps and not evidence that eight physical fixtures exist. Their count is currently eight for every model, including 56/57-row widebodies and the five-row G650 model, so that count does **not** satisfy the requested aircraft-length/row adaptation by itself.
- A full name scan of all 29 GLBs found no named reading-light, passenger-service-unit, passenger-call-button, or attendant-call components. Existing `reading` controls must not be presented as real modeled PSU hardware.
- Seat component naming differs by asset family. Aircraft dimension GLBs include names such as `Seat row N position M ...`; airline mesh reconstructions use airline/seat identifiers such as `Emirates first seat 1A ...`. Build inventory parsing against the actual catalogs/manifests rather than assuming one seat naming pattern.
- Cabin geometry and many fixture positions are authored simulation geometry, not OEM or airline-installed cabin CAD. Preserve the profile source and its accuracy note in the inspector/export evidence.

## Implementation requirements

1. Extend the generated per-profile inventory with exact, model-specific fixture/anchor identities and counts. Preserve empty locators as *anchors* with that explicit meaning; do not call them fixture meshes. Read world-space transforms in Three.js so nested nodes are positioned correctly.
2. Use each profile's actual layout/seat-row data to decide which independent controls exist. Do not impose a fixed count of five or reuse one generic count for every model. If the provided source does not establish the installed fixture count/position, expose only a clearly identified visual-simulation control where the source supports it; document missing as-installed/OEM evidence rather than claiming a real aircraft fit.
3. Independently address the existing cove meshes, sidewall strips/anchors, and individual window panes where their model geometry supports that mapping. Keep legacy group zones and old scene/project imports compatible; define how a group mood track supplies initial values to new fixture tracks without coupling later per-fixture edits.
4. Investigate model-specific reading-light and call-button data before building PSU fixtures. Current GLBs contain no such named components. Research manufacturer cabin drawings and airline seat/product information where available. Seat maps alone do not establish PSU hardware. If verified data/geometry remains unavailable for a profile, do not fabricate a real fixture position or claim an authentic installed fit; continue implementing the independently supported fixture classes.
5. Keep selectable source markers and RGBW effects tied to their exact fixture/anchor IDs. Selecting a marker must select only its matching option in the existing Zone Inspector. Color/intensity changes, scene playback, keyframe capture, undo/redo, save/load, project switching, and export must preserve independent fixture values.
6. Keep all new sources simulation-only. Do not connect, arm, or send commands to physical hardware.
